# Repair Service Material Pricing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist and present services, included materials, and separately charged parts without double charging, while applying server-verified wholesale pricing.

**Architecture:** Add a closed `line_type` discriminator to repair cost lines and their immutable revision snapshots. Extend the shared pricing engine so services contribute revenue, included materials contribute only internal cost, and charged parts contribute both revenue and cost; then make the API re-resolve catalog prices and stock rules before the existing atomic inventory RPC writes anything. Render the resulting groups through focused presentation components instead of adding more conditional markup to the already-large repair form.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, React Hook Form, Zod, Supabase/PostgreSQL, Vitest, Testing Library, MSW, Tailwind CSS, jest-axe.

**Spec:** `docs/superpowers/specs/2026-08-21-repair-service-material-pricing-design.md`

## Global Constraints

- Existing repair lines default to `charged_part`; no historical row may be reclassified automatically.
- Allowed values are exactly `service`, `included_material`, and `charged_part`.
- A service catalog line never consumes inventory.
- An included material has zero additional customer price and contributes internal cost only.
- Wholesale status, current catalog prices, organization, branch, and stock are authoritative on the server.
- If a verified wholesale customer has no positive wholesale price, use retail price and expose `Sin tarifa mayorista configurada`.
- Internal cost and margin are visible only with `cost_prices.read` or an equivalent role accepted by `useCanViewCost`.
- Do not add a BOM editor or new dependency.
- Create migrations with `npx supabase migration new`; do not hand-author an untracked migration filename.
- Preserve creation idempotency and the separation between delivery status and payment status.

export const REPAIR_LINE_TYPES = ['service', 'included_material', 'charged_part'] as const
export type RepairLineType = typeof REPAIR_LINE_TYPES[number]
export function normalizeRepairLineType(value: unknown): RepairLineType {
  return REPAIR_LINE_TYPES.includes(value as RepairLineType) ? value as RepairLineType : 'charged_part'
}
export const isInventoryLine = (value: RepairLineType) => value !== 'service'
