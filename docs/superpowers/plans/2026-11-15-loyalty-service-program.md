# Fidelización para servicios

Alcance autorizado: programa por monto, turnos atendidos y cobrados, o ambos; separar configuración, progreso de clientes y sorteos. Conservar saldos y canje real por saldo a favor. No prometer un servicio gratis restringido: requiere un flujo de canje específico posterior.

1. Migración local: modos compatibles, registro único por turno, conteo autorizado y métricas.
2. API y configuración: detección de capacidad, errores visibles, validación.
3. Interfaz adaptable: programa, clientes, sorteos opcionales; ejemplos y progreso real.
4. Pruebas SQL, tipos, lint y revisión visual con fixtures.

No aplicar migración, escribir producción ni publicar. Los registros nuevos son prospectivos; no se reconstruyen visitas históricas a partir de movimientos financieros.
