# Atomic Repair Credit Payment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register repair financing, installments, payment ledger, and repair balance atomically and idempotently.

**Architecture:** Extend the existing service-role-only PostgreSQL closure RPC with optional credit terms. Keep tenant resolution and fast UX checks in the route, but move all authoritative credit validation and writes into the same database transaction as the repair payment.

**Tech Stack:** Next.js 16 route handlers, TypeScript, Zod, Supabase/PostgreSQL PL/pgSQL, Vitest.

## Global Constraints

- Preserve existing cash, card, transfer, delivery, and POS RPC callers.
- Scope every database operation by organization and branch where applicable.
- Keep `SECURITY DEFINER`, `search_path = ''`, and service-role-only execution.
- Do not touch unrelated dirty files.
- Do not claim remote deployment without applying and verifying the migration remotely.
